# MOCK_SCENARIOS — сценарии мок-сервера

Приёмка 04_MOCK_SPEC §7.3: каждый сценарий воспроизводим и описан с ожидаемым видом UI.

**Как включить:** параметр `?scenario=<имя>` при загрузке страницы (например `http://localhost:5173/?scenario=quality`) или плавающая панель «⚙ Мок» внизу слева (только при `VITE_USE_MOCK=true`). Панель также умеет: ускорение времени ×1/×60, тумблеры «терять ack» и «модем отклоняет», сброс данных.

Пользователь: `demo` / `demo` (только мок).

## Поведение команд (04 §3, сводка)

- `queued → sent_gw`: класс C 2 с, класс A 20 с; `sent_gw → acked`: 3 с / 5 с; `acked → completed`: по duration с ускорением ×60 (30 мин = 30 с).
- Тумблеры панели: потеря ack → timeout через 12 с; result_code=1 → rejected; модем offline → команда queued с `MODEM_OFFLINE` и TTL 30 мин (при ×60 — 30 с) → cancelled.
- Идемпотентность: повторный POST `/commands` с тем же `idempotency_key` → 200 с той же командой.
- `on` без длительности → подставлен `default_duration_s`; больше `max_duration_s` → 422 `DURATION_OVER_MAX` без урезания.
- Новая команда того же устройства гасит неотправленную прежнюю (`superseded`).

## Допущения мока ([ASSUMPTION], до решения по контракту)

- RATE_LIMIT отдаётся как HTTP 429 (В5/BR-FE-3).
- Прогнозный тег имеет id `EXT0000000000001/9/0/1` (внешний источник); его `ts_measured` — ближайший прогнозируемый час.
- БС в контракте нет: `link_loss` влияет только на модемы/теги (В3/BR-FE-1).
- Внешние источники не эмулируются (В4/BR-FE-2).
- Разделы `/settings/*` отдаются массивами; схема контракта для них — `type: object` (BR-FE-4): тест-сверка проверяет их ослабленно (массив или объект).
- Команда `on` при политике `always` у offline-модема сначала проходит `awaiting_confirm`, TTL стартует после подтверждения (§3.1 п.4 и п.6).
