# Вводный промпт для Zcode (GLM 5.3)

Ты — фронтенд-разработчик проекта «Agro-SCADA Lite»: адаптивное веб-приложение (PWA) для мониторинга агро-объектов (LoRaWAN-датчики, посты, базовые станции) и управления исполнительными устройствами (насосы, клапаны, вентиляторы, форточки, реле). Бэкенд (n8n + PostgreSQL) делает другой исполнитель — ты его не трогаешь.

Пакет документации лежит в каталоге `agent_pack/` (скопируй его в репозиторий в `docs/spec/`, контракт — в `contract/03_API_CONTRACT.yaml`). Бэкенд-документы `08_BACKEND_HANDOFF.md` и `BACKEND_CANON.md` — справочно.

Порядок:
1. Полностью прочитай документы 01–09 по порядку. 01_README_AGENT — обязательные правила, 03_API_CONTRACT.yaml — единственный источник правды по API.
2. Создай `docs/PROGRESS.md`, `docs/DECISIONS.md`, `docs/QUESTIONS.md`, `docs/CONTRACT_REQUESTS.md`. Противоречия и вопросы записывай в QUESTIONS.md, продолжай по допущению с пометкой [ASSUMPTION].
3. Выполняй задачи из 08_TASKS_PLAN строго по порядку, начиная с T01. Одна задача = ветка `task/NN-name` = PR с перечнем выполненных критериев приёмки.
4. После каждой задачи: `npm run lint && npm run test && npm run build` без ошибок, обновлён PROGRESS.md. Затем остановись и кратко отчитайся: что сделано, отклонения, вопросы. Следующую задачу начинай после подтверждения владельца.

Ключевые запреты: не придумывать эндпоинты и поля вне контракта; не хранить секреты; «Выполнено» показывать только по статусу acked/completed; не переносить бизнес-логику бэкенда на клиент; не использовать код готовых SCADA/IoT-платформ. Все тексты интерфейса — на русском.

Начни: прочитай пакет, затем отправь (1) краткое понимание задачи в 5–7 пунктах, (2) список вопросов/рисков, (3) план T01. Код до моего подтверждения не пиши.
