# 04_MOCK_SPEC — мок-сервер

Версия 1.0 · 20.11.2026. Реализация: MSW в `src/mocks/`, включается `VITE_USE_MOCK=true`. Мок строго следует 03_API_CONTRACT.yaml (проверять типами, сгенерированными из OpenAPI, напр. openapi-typescript).

## 1. Набор данных (seed, `src/mocks/seed.ts`)
- 1 хозяйство «АгроЭЛЕМЕНТ-Демо»; 2 объекта: «Виноградник Золотая Балка» (vineyard), «Насосная-1» (pump_station). tz Europe/Moscow.
- 2 БС: bs1, bs2. 15 постов (12 на винограднике, 3 у насосной), координаты в радиусе 600 м от 44.53, 33.70.
- 15 модемов: 11 класса A (только датчики, интервал 900 с), 4 класса C (с исполнителями, интервал 300 с).
- Каналы (3–5 на пост): t воздуха (01, +150 см), влажн. воздуха (02, +150), влажн. грунта (03) на −10/−30/−60, t грунта (04, −10), давление системы (06, 0) у насосной, осадки (09) на 1 посту, влажн. листа (08) на 2 постах.
- 2 канала status 'unassigned', 1 канал 'unknown_code' (code 0x7A).
- 6 исполнителей: насос (pump, max 4 ч), 3 клапана (valve, default 30 мин, max 4 ч), вентилятор (fan), форточка (window). Политики: насос — always, клапан 1 — manual_only, остальные — manual_and_rule_approval.
- Прогноз осадков (kind forecast) на 48 ч вперёд для виноградника.
- Пользователь: login `demo`, пароль `demo` (только мок).

## 2. Генерация значений
- История 30 дней, шаг = интервал модема; суточные синусоиды: t воздуха 4–14 °C, RH 60–95 %, влажн. грунта 18–35 % (падает, после полива +6 % за 1 ч), давление 2,5–3,2 бар при работе насоса, 0 при выключенном.
- Новые значения: каждые 60 с мок «принимает пакет» от 1–3 случайных модемов (ускоренное время для живости UI).
- 5 % значений с origin 'backlog' (догружено).

## 3. Поведение команд
POST /commands проходит проверки как в 08_BACKEND_HANDOFF п. 3.1 (режим, длительность, политика, idempotency). Далее по таймерам:
| Переход | Задержка класс C | Класс A |
|---|---|---|
| queued → sent_gw | 2 с | до следующего «аплинка» (имитация 20 с) |
| sent_gw → acked | 3 с | 5 с |
| acked → completed | по duration (в моке ускорение ×60: 30 мин = 30 с) | так же |
Настраиваемые сбои (панель отладки, см. п. 5): потеря ack → timeout через 12 с; result_code=1 → rejected; модем offline → warning MODEM_OFFLINE, expires_at +30 мин (в моке +30 с) → cancelled.

## 4. Сценарии (переключатель `?scenario=` или панель отладки)
| Сценарий | Что происходит |
|---|---|
| normal | всё в норме, 1 тревога P3 |
| quality | на разных постах: stale, offline, out_of_range, sensor_error, forecast, sim, backlog — для проверки виджетов |
| pressure_drop | через 20 с давление падает до 1,2 бар → тревога P1 modem_immediate active_unacked; через 40 с escalation_step=1, через 60 с — 2 |
| link_loss | bs1 offline, 4 модема offline, их теги stale |
| cmd_fail | все команды → timeout |
| manual_mode | клапан 2 в manual, расписание даёт schedule.skipped в журнале |
| onboarding | появляется новый модем с 4 unassigned каналами |
| empty | нет объектов (первичная настройка) |

## 5. Панель отладки (только при моке)
Плавающая кнопка «⚙ Мок» внизу слева: выбор сценария, тумблеры сбоев команд, ускорение времени ×1/×60, сброс данных. В прод-сборке (`VITE_USE_MOCK=false`) код мока и панели не попадает в бандл.

## 6. /updates
Мок хранит журнал изменений с server_ts и отдаёт всё, что новее since. Это обязательно: UI должен работать только через /updates, без полной перезагрузки списков.

## 7. Приёмка мока
1. Все пути из 03_API_CONTRACT отвечают по схеме (тест сверяет ответы со схемой).
2. 401 при отсутствии токена; login demo/demo выдаёт токен.
3. Каждый сценарий п. 4 воспроизводим и описан в `docs/MOCK_SCENARIOS.md` с ожидаемым видом UI.
